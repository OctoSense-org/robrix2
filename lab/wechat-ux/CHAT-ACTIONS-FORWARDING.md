# Chat actions and message forwarding

Chat-list rows expose **Read/Unread**, **Hide**, and **Delete** on a left drag or trackpad swipe. Right-click/long-press also offers these actions. Mark unread uses the existing Matrix SDK unread flag; marking read uses the user's read-receipt privacy preference.

Hide removes the row while keeping membership and history. Searching or opening it through Contacts restores the row; newer activity also restores it. Delete asks for confirmation, hides the row, and applies a timestamp cutoff to its Robrix timeline and message selection. It does **not** leave/forget the room, redact events, erase the SDK's media cache, or delete server history. Hide and Delete preferences are stored per account **on this device**, in `persistent_state/chat_visibility.json`; other Matrix clients and devices retain their history. Group membership is unchanged.

To forward, right-click/long-press a sent message and choose **Select / Forward**. Select up to 100 messages from the loaded timeline, choose one or more joined conversations, then choose **Individually** or **As chat history** and tap **Send**. Load older messages in the source chat first if needed.

- Individual forwarding creates new messages under the forwarding user's identity, in source order. It preserves Matrix message content, including attachment descriptors and mini-app cards, while dropping the original room's reply/thread relations and mention metadata.
- A bundle is a `m.room.message` with custom msgtype `rs.robius.robrix.forwarded_chat`, structured sender/time/content data, and a readable `body` fallback. Robrix renders a chat-history card that opens the full text and attachment names. Other clients can display the fallback. Embedded sender labels are supplied by the forwarder and are not authenticated original events. Inline attachment playback in the history viewer is not implemented.
- Bundles are limited to 32 KB of serialized content to leave room for encrypted-event overhead. Oversized selections offer fewer messages or individual forwarding.
- Sends use `Room::send`, so destination-room encryption applies. The recipient picker labels unencrypted/unknown destinations. One transaction ID is retained per message and recipient; after a partial failure, **Retry Remaining** resumes with the same IDs and does not replay confirmed sends. Sends stop if the active account changes.

Physical Mac trackpad behavior and iOS device behavior require separate hands-on verification; native pointer dragging exercises the row gesture/action flow. Unit tests cover direction normalization, persisted hide/clear state, forwarding order, content compatibility, and bundle validation. No visual-similarity score is inferred from functional tests.

Verified on macOS on 2026-09-20: the build and all 153 library tests passed. Ten native Palpo checks passed with zero native UI errors: unread account data, ordered individual sends, structured bundles and fallback text, opening a received history card, encrypted sending, two-recipient partial-failure retry without duplicates, Hide across restart, restoring a hidden chat from search, canceling Delete, and Delete across restart followed by new activity. The last check also verified unchanged room membership and retained server history. A separate wire audit confirmed two new encrypted events and no plaintext message events in the encrypted destination during this run; the native sender rendered the decrypted messages. Recipient-device decryption was not tested.
